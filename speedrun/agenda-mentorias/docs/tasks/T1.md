# T1 · Agendar mentoria

`POST /agendamentos` · arquivo: `src/rotas/agendamento.js` · registrar em `src/app.js`

Corpo: `{"vagaId": number, "jovemEmail": string}`

## Casos (na ordem em que as validações acontecem)

| Quando | Status | Corpo |
|---|---|---|
| `vagaId` ausente ou não inteiro | 400 | `{"erro":"vagaId é obrigatório"}` |
| `jovemEmail` ausente ou vazio | 400 | `{"erro":"jovemEmail é obrigatório"}` |
| `jovemEmail` sem formato `a@b.c` | 400 | `{"erro":"jovemEmail inválido"}` |
| vaga não existe | 404 | `{"erro":"Vaga não encontrada"}` |
| vaga não está livre | 409 | `{"erro":"Vaga indisponível"}` |
| sucesso | 201 | `{"id","vagaId","mentorId","jovemEmail","status":"confirmado"}` e a vaga passa a `livre: false` |

## O Par

- ✅ **Funciona:** `{"vagaId": 1, "jovemEmail": "ana@pda.org"}` → `201 {"id":4,"vagaId":1,"mentorId":1,"jovemEmail":"ana@pda.org","status":"confirmado"}`
- ❌ **Falha:** `{"vagaId": 3, "jovemEmail": "ana@pda.org"}` → `409 {"erro":"Vaga indisponível"}` (a vaga 3 já está ocupada no seed)

## NFR-1 (desafio)

Várias requisições ao mesmo tempo para a mesma vaga livre: exatamente uma recebe 201. Dica: o repositório tem um `await` entre ler e escrever (ADR-001).
